Analyze the project and produce a complete, implementation-ready list of requirements.

- **Features:** All functional and non-functional requirements, including technical and business constraints.
- **UI/UX:** Where elements appear, what users see, available interactions, and how the UI responds to each action.
- **User flows:** Steps, navigation, decision points, and alternate paths.
- **System behavior:** Business logic, state changes, data flow, permissions, validations, and integrations.
- **Edge cases:** Errors, empty states, failures, invalid inputs, and recovery behavior.
- **Acceptance criteria:** Specific, testable conditions for each requirement.

Use short, precise bullet points. Cover all relevant details without repetition or unnecessary explanations. Don't write code or implementation plans. Don't invent requirements; clearly separate assumptions and open questions. Use existing project context and ask questions only when essential information is missing.

The output must be detailed enough that developers can implement the requirements and testers can verify them without guessing.
